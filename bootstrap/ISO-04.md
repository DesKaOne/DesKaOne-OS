# DesKaOne OS — Bootstrap 04 ISO Readiness R1

**Scope: source-only planning and preflight guards.** This change does not build or claim a bootable ISO. It leaves the existing live-build configuration and scripts unchanged.

## Target
- Debian 13 Trixie, amd64, live-build ISO-hybrid candidate.
- Existing Bootstrap 01 build script is a *candidate*, not evidence of successful boot.
- Existing live-build configuration explicitly uses `--debian-installer none`; this stage does not introduce an installer.
- Desktop and Server profiles remain inactive; this is a **shared base** candidate, not an edition-specific ISO.

## Preflight
From `bootstrap/`, the manual command `bash scripts/validate-iso-source.sh` runs the existing source-only validators and checks the build-script intent, package lists, and absence of activated edition configuration. It performs no `lb config`, `lb build`, package download, host modification, or VM execution.

## Proposed build gate (requires separate approval)
1. Use a clean, disposable, documented Debian 13 amd64 build environment with pinned package sources.
2. Confirm live-build and all requested packages resolve; record versions and apt metadata.
3. Review the live-build configuration for reproducibility, bootloader/UEFI and BIOS behavior, firmware policy, and output naming.
4. Only then authorize `bash scripts/prepare-build.sh` and `bash scripts/build-iso.sh` in the isolated build environment.
5. Record resulting artifact checksum and build log, without declaring bootability until boot tests pass.

## Proposed runtime gate (requires separate approval)
- Boot ISO in a disposable VM with BIOS and UEFI modes.
- Confirm login/session policy, live filesystem, systemd startup, network isolation, and absence of unexpected open services.
- Verify no installer, edition-specific service activation, or automatic SSH exposure.
- Capture failures, logs, and reproducibility metadata before any release candidate designation.

## Known risks and deferred decisions
- No package-resolution test or ISO build has been run.
- Bootloader, firmware, graphical and virtual hardware compatibility are unverified.
- `systemd-resolved` may still arrive transitively; absence from explicit lists does not guarantee absence from the final image.
- `dnsmasq` is in the shared base list; runtime service enablement and port ownership need review before a build gate.
- `sysctl` forwarding defaults are disabled; any future router edition needs a separately reviewed override.
- Live-build config generated by `lb config` must be inspected before execution, including image contents and archive settings.
- No GitHub Actions or CI workflows are introduced.
