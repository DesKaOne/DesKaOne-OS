# Contributing to DesKaOne OS

Thanks for your interest! The project is in **architecture/documentation stage**, not ready for installation.

## Welcome contributions
Documentation improvements, threat-model reviews, hardware support research, package policy suggestions, accessibility and UX design, translations and Architecture Decision Record proposals.

## Before opening a pull request
1. Read [Architecture](docs/architecture/ARCHITECTURE.md), [Roadmap](ROADMAP.md) and [AGENTS.md](AGENTS.md).
2. Open an Issue for substantial changes and discuss scope first.
3. Keep changes focused, explain rationale and compatibility/security impacts.
4. State what was verified; do not claim tests you did not run.
5. Do not add implementation, images, packaging or CI without explicit maintainer phase authorization.
6. Do not include secrets, proprietary third-party assets or copied content without license compatibility review.

## Pull requests
Use clear English titles and descriptions. Reference an Issue when applicable. Maintainers may request an ADR for architecture-impacting changes. A pull request does not imply approval for deployment or release.

## Licensing
By contributing, you agree that your original contribution may be distributed under the repository's applicable license; identify any files requiring a different compatible license. Third-party components keep their own licenses.

## Community
Follow [Code of Conduct](CODE_OF_CONDUCT.md). Report security concerns privately using [SECURITY.md](SECURITY.md), not public Issues.
